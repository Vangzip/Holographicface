# 泊松重建 RGB 回填设计

## 背景

当前泊松重建输入使用 `pcl::PointXYZRGBNormal`，输入点仍携带 RGB。
但是 PCL 泊松算法根据隐式曲面生成全新的等值面顶点，输出网格只含
XYZ，PLY 因此没有 `red`、`green`、`blue` 字段。

仓库及上级 `Holo`、`virtualcamera`、`FLVS` 工程中存在旧的
`texturemeshPoisson::mergeMeshRGB`。该函数体现了“重建后回填颜色”
这一处理位置，但不能直接复用：

- 函数入口立即返回 `false`，实际逻辑被禁用；
- 它把泊松顶点索引当作原始点云索引，两套顶点并不一一对应；
- 泊松顶点数与原始点数不同，直接索引会产生错误颜色或越界风险。

本次保留旧逻辑的处理时机，用空间邻域匹配替换不正确的索引匹配。

## 目标

- 泊松重建的内存网格和落盘 PLY 均包含 RGB 顶点颜色。
- 颜色来源限定为实际参与泊松重建、且具有有效法线的点云。
- 泊松网格几何和三角面索引不因填色发生变化。
- 贪婪重建行为保持不变。
- 默认重建与保存链路继续采用纯内存传递。

## 非目标

- 不增加相机图像的 UV 投影或纹理贴图。
- 不修改泊松几何参数或贪婪重建参数。
- 不恢复旧的按索引拷贝实现。
- 不增加用户可配置的邻点数量；首版固定使用三个邻点。

## 方案选择

### 方案一：恢复原索引拷贝

开销最低，但泊松输出顶点不是原始点云的子集，索引没有对应关系。
该方案不正确，不采用。

### 方案二：单最近邻

为每个泊松顶点复制最近原始点的 RGB。实现简单、速度快，但在人脸的
连续肤色区域容易产生色块或散斑。

### 方案三：三个邻点距离加权

为每个泊松顶点查询三个最近原始点，按距离倒数加权 RGB。它比单最近邻
平滑，同时查询规模远小于泊松求解本身。

采用方案三。

## 架构与数据流

在 `vendor/point_cloud` 模块内增加一个与文件 IO 无关的颜色回填函数。
该函数接收最终 `pcl::PolygonMesh` 和彩色源点云，在内存中更新
`mesh.cloud`。

处理顺序：

1. 对输入 RGB 点云执行现有体素过滤和法线估计。
2. 丢弃法线无效的孤立点，形成 `PointXYZRGBNormal` 源点云。
3. 执行泊松重建。
4. 执行现有凸包裁剪和未使用顶点清理。
5. 对裁剪后的最终网格执行 RGB 回填。
6. 返回带 RGB 的内存网格，由现有持久化层按需写出 PLY。

把回填放在裁剪后可以减少查询数量，并确保颜色只写入最终保留的顶点。

## 颜色回填算法

1. 将最终网格顶点读取为 `pcl::PointXYZ`。
2. 使用有效的 `PointXYZRGBNormal` 源点云构建 KD-Tree。
3. 对每个网格顶点查询最多三个最近邻：
   - 如果最近距离接近零，直接复制最近点 RGB；
   - 否则使用欧氏距离倒数作为权重；
   - 分别计算 R、G、B 的加权平均并四舍五入；
   - 将结果限制在 `0..255`，Alpha 设为 255。
4. 构造与原网格顶点数量、顺序完全一致的 `PointXYZRGB` 点云。
5. 用彩色点云替换 `mesh.cloud`，保留原三角面数组不变。

KD-Tree 返回平方距离，因此加权前取平方根。距离零判断使用一个固定的
小阈值，避免除零。

## 接口边界

颜色回填作为 `poissonmesh` 模块中的独立函数，不读取配置文件，不访问
磁盘，也不依赖输出目录。`ConverPointCloud` 只负责按顺序调用：

`泊松重建 → 裁剪 → 颜色回填`

这样文件输入、纯内存输入和未来其他输出适配器都共享相同结果。

旧 `texturemeshPoisson::mergeMeshRGB` 保持不参与当前主链路，避免扩大
本次修改范围；新实现复用它所表达的“重建后回填”职责，而不是复用错误
的索引算法。

## 错误处理

以下任一情况导致颜色回填失败，并使整个泊松重建返回失败：

- 源点云为空；
- 网格为空或无法解析出顶点；
- KD-Tree 对任一网格顶点未返回邻点；
- 回填后的顶点数与原网格顶点数不一致；
- 回填后网格不含 RGB 字段。

失败时输出包含 “Poisson color transfer” 的明确日志。不得静默保存无色
泊松网格。

## 测试

采用测试先行：

1. 扩展现有泊松内存重建测试，先断言输出网格包含 RGB 字段，并确认修改
   前测试因字段缺失而失败。
2. 增加小型确定性颜色回填测试：
   - 精确重合顶点复制精确颜色；
   - 位于三个彩色点之间的顶点得到距离加权颜色；
   - 三角面索引和顶点数量保持不变。
3. 增加空源点云失败测试。
4. 运行完整 `mesh_reconstruction_tests`。
5. 运行项目现有六组回归测试。
6. 按既定构建规则终止正在运行的 `mergeholo.exe`、确认
   `mergeholo_verify.exe` 不存在，并重新构建正式
   `00-bin/mergeholo.exe`。
7. 使用 `samples/face_roate/0_rgb.ply` 重新运行泊松重建，核对：
   - PLY 头包含 `red`、`green`、`blue`；
   - 网格可正常加载；
   - 记录颜色回填后的总耗时、顶点数、三角面数和文件大小。

## 验收标准

- 泊松输出 PLY 包含 `uchar red`、`uchar green`、`uchar blue`。
- 每个泊松顶点都有有效 RGB，且顶点数和三角面连接关系与填色前一致。
- 颜色回填失败时不产生成功结果。
- 贪婪输出及其 RGB 行为不变。
- 所有相关测试和完整回归测试通过。
- 正式产物只有 `00-bin/mergeholo.exe`，不生成或保留
  `mergeholo_verify.exe`。
