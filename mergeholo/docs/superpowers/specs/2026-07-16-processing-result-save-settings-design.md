# 处理结果保存设置设计

**日期：** 2026-07-16
**状态：** 已确认
**范围：** CaptureWindow 保存设置 UI、处理流水线可选结果落盘

## 1. 目标

在主拍照处理窗口的“打印配置”按钮后增加“保存设置”按钮。用户可以在弹窗中任意组合选择保存 mesh、multiview 和 elemental 三类处理结果。

处理主链继续使用现有内存数据。只有被勾选的结果才额外写入 `output`；默认全部不勾选，程序重启后也恢复为全部不勾选。可选结果写盘失败只产生警告，不得中断内存处理或打印。

## 2. 非目标

- 不把保存设置写入永久配置，不跨程序启动保留。
- 不切回旧版文件输入输出主链。
- 不改变 elemental 内存结果交给 `PrintJobRunner` 的方式。
- 不清理或覆盖历史保存结果。
- 不改变拍照输入、运行时 INI 和流水线日志当前已有的落盘行为。

## 3. UI 与交互

### 3.1 主窗口

在 `CaptureWindow` 底部按钮区的“打印配置”右侧增加“保存设置”按钮，沿用现有按钮尺寸、边框、字体和禁用样式。

“保存设置”在流水线处理期间禁用，其他非处理状态可用，避免同一次运行中途改变保存选项。

### 3.2 保存设置弹窗

弹窗按参考图布局，提供三个可独立多选的圆形复选框：

1. 保存 mesh 结果
2. 保存 multiview 结果
3. 保存 elemental 结果

弹窗打开时回显 `CaptureWindow` 当前会话内的选择。

- 点击“确认”：用当前勾选组合更新会话设置并关闭弹窗。
- 点击“取消”：将三个会话设置全部清空并关闭弹窗。
- 点击右上角关闭按钮或系统关闭按钮：行为与“取消”一致，清空三个设置。

设置仅保存在当前 `CaptureWindow` 实例中。实例创建时三个选项均为 `false`，不使用 `QSettings` 或其他持久化机制。

## 4. 配置与运行快照

`CaptureWindow` 在一次处理开始时冻结当前保存设置，并生成该次运行共用的本地时间戳：

```text
yyyyMMdd_HHmmss_zzz
```

例如：

```text
20260716_153045_123
```

生成的 `holo_config.ui.ini` 增加以下字段：

```ini
mesh_out_dir=mesh
save_mesh_result=false
save_multiview_result=false
save_elemental_result=false
result_timestamp=20260716_153045_123
```

流水线配置解析器为这些字段提供安全默认值。旧配置不包含字段时，三个保存开关均视为 `false`。

本次处理启动后，即使以后重新打开弹窗，也不能改变已启动运行的保存快照。

## 5. 目录与文件命名

三个保存项使用同一个运行时间戳，并在 `output` 下使用带时间戳后缀的独立目录。未选择的目录不创建。

```text
output/
  mesh_20260716_153045_123/
    0_mesh.ply
  multiview_20260716_153045_123/
    001001.jpg
    ...
    270270.jpg
  elemental_20260716_153045_123/
    001001.jpg
    ...
    150150.jpg
```

历史目录不在新处理开始前删除，也不被新运行覆盖。

multiview 文件继续使用 `view_name_digits` 和一基行列编号。elemental 文件继续使用目标行数、列数的十进制位数和一基行列编号。默认配置下分别对应 `001001...270270` 和 `001001...150150`。

## 6. 流水线数据流

主流程保持为：

```text
深度输入 -> 内存 mesh -> 内存 multiview -> 内存 elemental -> PrintJobRunner
                |              |                    |
             可选 PLY       可选 JPG             可选 JPG
```

写盘逻辑只读取阶段已经生成的内存结果，不替代内存结果，不把下游改为文件读取，也不提前释放内存。

### 6.1 Mesh

内存网格创建成功后，若 `save_mesh_result=true`，将 `MeshMemoryResult` 中的 `pcl::PolygonMesh` 保存为当前时间戳目录下的 `0_mesh.ply`。下游 multiview 仍直接消费同一个内存网格。

### 6.2 Multiview

GPU atlas 渲染和帧回读完成后，若 `save_multiview_result=true`，从 `MemoryFrameSink` 保存所有视图 JPEG，然后再进入 elemental 阶段。

保存器必须处理 OpenGL 内存帧的 bottom-up 行方向和 RGB 色序，使输出 JPEG 的方向、颜色及编号与旧版 `modelMoveHandler` 文件输出一致。JPEG 质量使用现有 `jpg_quality` 配置。

### 6.3 Elemental

内存 elemental 重排完成后，若 `save_elemental_result=true`，从物化的 `ElementalMemoryResult` 保存所有目标 JPEG。保存不重新执行 elemental 重排，也不改变内存图像布局。

文件方向、RGB 色序、行列编号和 JPEG 质量与旧版 elemental 文件输出一致。

## 7. 写盘失败语义

可选结果保存采用尽力而为语义：

- 创建时间戳目录失败、单个文件写入失败或编码异常，都记录为保存警告。
- 保存警告不改变阶段成功状态，不改变流水线退出码。
- 后续处理阶段继续运行。
- 已生成的 elemental 内存结果仍交给 `PrintJobRunner`，打印配置窗口照常打开。
- 已写出的部分文件和所有历史目录均保留，不做自动清理。
- 保存警告包含结果类型、目录和首个错误原因，并写入流水线日志。
- 打印配置窗口关闭后，主窗口汇总弹出一次“部分结果保存失败”警告，避免在启动或执行打印前阻断用户。

拍照输入、运行配置等流水线启动必需文件如果无法准备，仍沿用现有致命错误行为；该规则不属于可选结果保存失败。

## 8. 代码边界

- `CaptureWindow`：持有会话设置、打开弹窗、冻结运行快照、生成时间戳、把开关写入运行 INI、展示保存警告。
- `SaveSettingsDialog`：只负责三个复选框及确认、取消、关闭语义，不直接访问流水线或文件系统。
- `PipelineConfig` / `HoloConfig`：解析可选保存开关、输出目录和运行时间戳，默认关闭。
- 结果保存模块：提供 mesh、multiview、elemental 的只读保存函数及统一警告报告。
- 各流水线阶段：在对应内存结果生成后调用保存函数；保存失败只追加报告。
- `PrintJobRunner`：不感知保存设置，不作修改。

## 9. 测试与验收

### 9.1 自动测试

- 旧配置缺少保存字段时，三个开关默认关闭。
- 三个开关可形成八种任意组合，只调用和创建已选择的结果输出。
- 保存设置弹窗确认后应用组合；取消和关闭后清空组合。
- 同一次运行的已选目录使用相同时间戳；不同运行不覆盖。
- 使用小型合成 PCL 网格保存 PLY，并重新读取验证顶点和面数据。
- 使用小型合成 multiview 缓冲保存 JPEG，验证数量、文件名、尺寸、颜色和上下方向。
- 使用小型合成 elemental 结果保存 JPEG，验证数量、文件名、尺寸和颜色。
- 使用不可写路径模拟保存失败，验证警告已记录且流水线结果仍成功。
- 未选择保存项时，不创建时间戳结果目录，现有内存结果保持可用。
- 现有 elemental 内存转换测试和打印模块测试继续通过。

### 9.2 集成验证

- 完成 Qt Release 构建。
- 使用缩小的 multiview/elemental 配置执行端到端处理，核对三类输出目录和文件。
- 分别验证全不选、单选、全选以及保存失败场景。
- 确认保存失败后仍能进入打印配置，并可由 `PrintJobRunner` 使用内存 elemental 数据打印。

## 10. 验收标准

1. 主窗口按钮位置和弹窗交互符合参考图及本设计。
2. 默认不保存三类处理结果，且所有处理和打印继续使用内存数据。
3. 三项保存设置支持任意组合，并仅在当前程序运行期间有效。
4. 已选结果写入带同一时间戳后缀的独立目录，历史结果不被清理或覆盖。
5. 文件命名、图像方向和颜色与旧版文件输出兼容。
6. 可选结果保存失败会被记录和提示，但不会中断处理或打印。
7. 自动测试、缩小配置集成测试和 Release 构建通过。
