# Pipeline Input Settings Design

**Date:** 2026-07-17

## Goal

Add an `Input Settings` workflow to the Qt capture window so an operator can start the existing holographic pipeline from RGB/depth, mesh, or multiview files. With no external input selected, the current camera-backed, all-memory pipeline remains unchanged.

## Confirmed Behavior

- The main window adds an `Input Settings` button before `Capture`.
- The dialog contains three mutually exclusive directory rows: RGB/depth, mesh, and multiview.
- Choosing a directory in one row immediately clears the other two rows.
- Dialog `Confirm` validates and stores the selection, then returns to the main window.
- Processing starts only when the operator presses the main window `Confirm` button.
- Dialog `Cancel` clears all input settings and restores the default camera workflow.
- External RGB and depth images are consumed in their stored orientation and are not rotated again.
- External input directories are read-only from the application's perspective: files are not copied, renamed, or deleted.

## Input Contracts

### RGB And Depth

The selected directory must contain exactly one same-basename pair:

- `<name>.jpg`
- `<name>.tiff`

The pair is loaded for preview and then passed to the existing depth stage. Depth, mesh, multiview, and elemental processing continue through the current in-memory path.

### Mesh

The selected directory must contain exactly one same-basename pair:

- `<name>_mesh.ply`
- `<name>.jpg`

The polygon mesh is loaded into a `MeshMemoryResult`, using the JPEG as its texture source. Depth and mesh generation are skipped. The current all-memory optimization then feeds the mesh directly to multiview rendering, followed by elemental generation.

### Multiview

The selected directory must contain the existing complete view grid, using the configured row, column, digit count, and image dimensions. With the default configuration this is `001001.jpg` through `270270.jpg`, each 150 by 150 pixels.

Depth, mesh, model, and multiview generation are skipped. The existing file-backed elemental input path consumes the selected directory.

## Stage Plan

| Input source | Depth | Mesh | Model | Multiview | Elemental |
| --- | --- | --- | --- | --- | --- |
| None/camera | Run | Run | Existing memory optimization | Run | Run |
| RGB/depth | Run | Run | Existing memory optimization | Run | Run |
| Mesh | Skip | Skip | Skip | Run from loaded mesh memory | Run |
| Multiview | Skip | Skip | Skip | Skip | Run from selected directory |

All successful paths still return an `ElementalMemoryResult` to the existing print workflow.

## Architecture

Introduce an explicit input-source model and run-plan builder instead of embedding stage rules in widget event handlers.

- `InputSourceSettings` represents `None`, `RgbDepth`, `Mesh`, or `Multiview` plus the selected directory.
- An input validator resolves the exact files and produces actionable validation messages.
- A pipeline run plan derives stage flags and input paths from the validated selection.
- `CaptureWindow` owns the confirmed selection, updates preview/button state, and writes the generated pipeline configuration.
- The pipeline preloads selected mesh files into `MeshMemoryResult` before stage execution.
- Existing multiview file loading remains the source for multiview input mode.

This keeps the UI independent from individual pipeline implementation details and gives tests one place to verify skip behavior.

## UI And State

- The dialog uses the existing Qt Widgets native Windows styling and spacing used by print and save settings.
- Path fields are read-only. Each row has a standard `Browse` button.
- `Input Settings` remains available while idle, after completion, and after camera initialization failure, so disk input can still be used.
- A confirmed RGB/depth selection displays its images in the existing preview panels.
- A confirmed mesh or multiview selection clears stale camera previews and enables the main `Confirm` action.
- While an external source is active, capture and retake are disabled so camera frames cannot silently replace the selected source.
- Clearing input settings resumes or retries the camera-backed idle state.

## Errors And Persistence

- Missing directories, ambiguous file sets, missing paired files, unreadable images, invalid mesh data, and incomplete multiview grids are reported in a native warning dialog before processing starts where possible.
- Runtime pipeline failures continue through the existing processing error dialog.
- Result write failures remain best-effort warnings and do not fail processing or printing.
- Save settings apply only to results generated by the current run. Imported source data is not duplicated into a new output directory.

## Verification

- Widget tests: mutual exclusion, confirm, cancel/clear, and native style invariants.
- Input tests: accepted and rejected RGB/depth, mesh, and multiview directories.
- Pipeline tests: all four stage plans and mesh-memory preload.
- Regression tests: no-selection camera flow and existing save settings behavior.
- Release build: kill any running `mergeholo.exe`, clean-build the official executable, ensure no `mergeholo.next.exe` remains, and perform a UI smoke check.
