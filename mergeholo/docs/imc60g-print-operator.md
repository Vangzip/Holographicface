# IMC60G 9030 打印操作手册

本手册适用于 Windows x64 版 `mergeholo` 的 IMC60G 打印模块。生产硬件固定为 IMC60G Card0、EtherCAT、逻辑 X 对应物理 Axis1、逻辑 Y 对应物理 Axis0，以及 SV660N 驱动内部位置比较输出 DO1+/DO1-。旧 DFJZH、Z/W 轴和 x86 打印链路不在本模块范围内。

## 首要安全规则

**打开“IMC60G 9030 打印”对话框不会开卡、不会启动 EtherCAT、不会解除软件急停、不会使能伺服，也不会回零或移动任何轴。**

只有操作员显式点击 **连接并回零** 后，程序才会开始开卡和硬件初始化。每次点击前必须重新确认：

- 现场人员已离开运动范围，X/Y 全行程无工具、工件、线缆或其他障碍；
- 物理急停可立即触及且功能已验证；只有确认现场安全后才允许解除急停；
- X/Y 负限位开关安装、接线和触发方向正确，回零方向有足够行程；
- 机械端位、软硬限位和回零回退距离不会造成碰撞；
- SV660N DO1+/DO1- 先接示波器、隔离输入或经批准的安全负载；未完成波形和极性验收前，禁止直接接入激光器等危险负载；
- 第二显示器已连接、启用且不是 Windows 主显示器；
- 不得在尚未由现场负责人确认上述条件时运行任何硬件验收脚本或手动运动。

软件的“停止/取消”不是物理安全回路的替代品。出现人员或设备危险时先按物理急停，再处理软件状态。

## 固定硬件映射与回零顺序

生产映射来自 `config/imc60g_print.ini`，程序会拒绝其他映射：

| 项目 | 固定值 |
|---|---|
| 控制器 | IMC60G，Card0 |
| 总线 | EtherCAT；打印前主站必须为 OP（状态 6） |
| 逻辑 X | 物理 Axis1 |
| 逻辑 Y | 物理 Axis0 |
| 回零顺序 | 先 Y（Axis0），后 X（Axis1） |
| 当前回零方向 | X/Y 均向负限位 |
| 当前回退量 | Y 92000 pulse；X 28000 pulse |
| 曝光源轴 | 逻辑 Y / Axis0 |
| 曝光输出 | SV660N 内部位置比较，DO1+/DO1- |

点击 **连接并回零** 后，程序按“发现并打开 Card0 → EtherCAT 扫描/初始化/启动 → 按配置处理软件急停状态 → 清轴状态 → Servo On → Y 负限位回零、回退、同步并置零 → X 负限位回零、回退、同步并置零”的顺序执行。任何一步失败都应停止后续动作并显示具体错误。

当前 SV660N 配置为 DO 功能 25、比较点 1、模式 0、比较宽度 1000、用户单位模式，正/负向属性分别为 129/130。这里的 `width=1000` 来自锁定的 `config/imc60g_print.ini` 硬件 profile；DO1 的实际开关窗口还由每行的 Y 位置比较起止点决定，**不是由旧 UI 的 `exposureSeconds`/“曝光时间”字段决定**。该旧字段不属于 active V2 硬件路径，现行打印 UI 不再提供它。DO1 的电压、电流、公共端、极性和负载接法必须以本机 SV660N 电气手册和经批准的现场接线图为准；软件参数不能替代电气隔离和负载校核。

## 部署与启动检查

运行目录必须是统一的 x64 部署，不要混入 x86 或旧 DFJZH 文件。至少检查：

- `mergeholo.exe` 为 x64；
- `IMC_Library_x64.dll` 与 `mergeholo.exe` 同目录，并与仓库 `vendor/imc60g/bin/x64/IMC_Library_x64.dll` 哈希一致；
- `config/imc60g_print.ini` 和可编辑的 `config/print_9030.ini` 位于程序识别的 `config` 目录；
- Qt x64 运行库、`platforms/qwindows.dll` 以及所用图片格式插件已随构建脚本部署；
- 构建期使用 `vendor/imc60g/include` 和 `vendor/imc60g/lib/x64/IMC_Library_x64.lib`；运行期不依赖 V2 源码目录；
- 启动诊断应记录进程架构、IMC DLL 绝对路径和 SHA-256、配置版本、Card0/X1/Y0 映射及 SV660N DO1 后端。启动诊断本身不得开卡。

可用 `scripts/verify_imc60g_sdk.ps1 -RuntimeDirectory <部署目录>` 检查 DLL 架构、哈希和必需导出。应优先使用 `scripts/build.ps1` 生成的完整部署目录，避免手工复制不一致的 DLL。

## 图像源与第二屏

对话框支持两种图像源：内存中的 elemental 结果，以及手动选择的图片文件夹。文件夹支持 JPG/JPEG、PNG、BMP、TIF/TIFF，按文件名不区分大小写排序；建议使用等宽零填充文件名（例如 `000001.png`），避免 `1.png、10.png、2.png` 的字典序歧义。

开始前，图像数必须严格等于“行数 × 列数”，所有图像的尺寸、像素格式和字节数必须一致且有效。正向行按 `0,1,2...` 显示，反向行按 `...2,1,0` 显示。

打印器只选择非主显示器，并从该物理输出读取实时刷新率。刷新率必须为有限正数，且当前运动速度、列间距和 VBlank 必须形成受支持的整数帧保持关系；无法选择第二屏、读取刷新率、建立 DXGI 输出或等待物理 VBlank 时，预检会在曝光和运动之前失败。运行中不要更改主/副屏、分辨率、刷新率、缩放或连接状态。

## UI 状态

| 状态 | 含义及允许操作 |
|---|---|
| 未连接 | 对话框已打开但硬件未初始化；只能准备图像/参数或点击“连接并回零” |
| 连接中 | 正在打开 Card0 和建立 EtherCAT；等待结果，不要重复操作 |
| 回零中 | 正在按 Y 后 X 的顺序找负限位、回退和置零；保持行程清空 |
| 就绪 | EtherCAT、Servo、回零和停止状态已验证；允许手动运动、开始或断开 |
| 打印中 | 打印参数和图像源锁定；允许请求暂停或取消 |
| 已暂停 | 已在安全行边界停下并解除曝光；允许继续或取消 |
| 安全停止中 | 正在执行取消/关闭清理；等待完成，不能关闭窗口或发新动作 |
| 故障 | 某项操作或安全验证失败；查看完整错误，消除原因后断开或重新连接并回零 |

硬件状态区分别显示 EtherCAT 是否 OP、X/Y Servo 是否 ON、X/Y Home 是否完成，以及计划位置（mm）。状态标签是软件读取结果，不替代现场目视检查。

## 参数、单位与约束

active V2 的可编辑值保存在版本 2 的 `config/print_9030.ini`。点击“开始”时会先保存当前界面值，再生成不可变打印任务。旧版 `move_adjust_mm`、`delay_seconds`、`exposure_seconds` 以及 Z/W 轴字段不参与 active V2 硬件路径，现行 UI 和版本 2 序列化均不再写出它们。不要在打印中编辑配置文件。

### 打印参数

| UI 字段 | 单位 | 当前含义 |
|---|---:|---|
| 行间距 | mm | 相邻打印行之间的逻辑 X 步进距离；换行时按 X 的 `细分 × 分辨率` 换算为 pulse |
| 列间距 | mm | Y 连续扫描中相邻列的物理间距；按 Y 的 `细分 × 分辨率` 换算，必须严格等于硬件配置的 1000-pulse 基准 |
| 行数 / 列数 | 个 | 打印网格尺寸；所需图像数严格为两者乘积 |
| 输出宽/高缩放 | 倍 | 第二屏图像目标尺寸倍率；必须为有限正数，结果不得超过 int32/QSize 范围 |
| 延长匀速段 | pulse | `add_temp_pulse`；增加 Y 匀速段并参与反向显示/曝光窗口计算，必须非负且不得溢出 SDK int32 位置范围 |
| 反向提前 | pulse | `lead_pulse`；修正反向行的显示起始延迟，必须非负且与其他补偿共同形成有效 VBlank 计划 |

当前两个配置文件必须彼此一致。特别是：

```text
axis_y.subdivision × axis_y.resolution × column_spacing_mm
    == imc60g_print.ini 中的 print.step_pulse（当前为 1000）
```

当前批准值为 Y `40 × 50 pulse/mm`、列间距 `0.5 mm`，结果正好是 `1000 pulse`。不相等时打印预检必然拒绝任务；不要通过绕过预检来“试跑”。

### X/Y 轴参数

| 字段 | 单位/含义 |
|---|---|
| 细分 | 无量纲；与分辨率共同决定每毫米脉冲数 |
| 分辨率 | pulse/mm 基因；程序实际使用 `细分 × 分辨率` 作为 pulse/mm |
| 运行速度 | pulse/s |
| 加速度 | pulse/s²；同时用于运动加速/减速参数 |
| 启动速度 | pulse/s；不得为负，Y 打印时不得高于运行速度 |
| 停止速度 | pulse/s；IMC `SetAxEndVel`，不得为负，Y 打印时不得高于运行速度 |
| 最大行程 | mm；限制单次手动相对移动，必须为有限正数 |
| 反向 | 勾选后翻转该逻辑轴的运动符号；修改前必须由现场确认方向 |

`config/imc60g_print.ini` 中的回零速度、加减速度、超时、稳定时间、最小移动量和回退 pulse 是受控硬件参数，不应由普通操作员现场试改。

## 标准操作流程

1. 完成首要安全规则中的现场检查，确认第二屏和安全 DO1 负载。
2. 启动 x64 程序并打开打印对话框。此时硬件必须保持未动作。
3. 选择内存 elemental 或图片文件夹，检查图像数量并用“预览”查看首帧。
4. 核对 Card0、X→Axis1、Y→Axis0、SV660N DO1 摘要和全部参数。
5. 点击 **连接并回零**；全程观察 Y 后 X 的运动方向、限位触发和回退，保持急停可触及。
6. 只有状态变为“就绪”，且 EtherCAT/Servo/Home 均正常后，才可做经批准的小距离手动验证或开始打印。
7. 点击 **开始**。程序会重新枚举第二屏、读取刷新率、生成 V2 时序，并检查卡、总线、急停、伺服、回零、停止、DO1 安全基线、图像和 VBlank；任一失败均不得运动或使能曝光。
8. 观察进度、状态、错误详情、第二屏帧序和设备运动。完成后程序会解除曝光、停止并验证 X/Y、按安全条件返回逻辑零点并释放第二屏资源。
9. 确认状态回到“就绪”后，才可点击 **断开**。断开负责停止、Servo Off、停止 EtherCAT 并关闭 Card0；故障时若断开未被验证，应保持物理急停并停止继续使用。

## 手动移动和停止

手动区只在“就绪”状态启用。输入“手动步距”（mm），再点击 X-/X+/Y-/Y+。程序按对应轴的细分、分辨率、速度、加速度、起/止速度、最大行程和“反向”设置生成相对运动；0、非有限值、超过最大行程或超出 int32 pulse 范围会被拒绝。

**停止** 会对映射后的 X（Axis1）和 Y（Axis0）均发送停止命令。若需要紧急停止，使用物理急停；不要等待 UI 停止按钮。

## 开始、暂停、继续、取消、关闭和断开

- **开始**：只在“就绪”且图像源有效时启用；执行完整预检后才允许曝光或运动。
- **暂停**：是线程安全请求，不会从 UI 线程直接调用 SDK。它在当前行完成、曝光已解除且 X/Y 停止验证后进入“已暂停”；不是任意脉冲位置的瞬时冻结。
- **继续**：只在“已暂停”启用；先重做动态硬件、DO1、第二屏和 VBlank 预检，再从下一行继续，不重复已完成帧。
- **取消**：在活动打印中请求公共安全清理；顺序为尽力解除曝光 → 停止 X/Y → 等待确认停止 → 仅在前三项都成功时返回逻辑零点并验证 → 关闭显示器资源。所有失败会合并报告，未验证安全时保持“故障”。
- **关闭**：打印/暂停/停止期间关闭窗口会先转为取消并等待安全停止完成；不能用强杀进程代替清理。遇到真正危险时先按物理急停。
- **断开**：只在“就绪”或可处理的“故障”状态启用；活动打印中必须先取消并等待清理完成。断开后 Servo、EtherCAT 和卡都应显示离线。

## 日志与错误码

可用于排障的记录位置如下：

- 对话框 `状态` 和 `错误详情`：当前操作的即时结果、预检失败和安全清理的聚合错误；
- 正常处理流水线日志：`<项目根目录>\runs\latest\output\pipeline.log`。它是图像处理流水线日志，不能代替 IMC 打印错误详情；
- 连接硬件验收记录：`<项目根目录>\runs\imc60g-acceptance\<时间戳>\acceptance.json` 和同目录 `print_flow.log`；每个阶段必须单独运行并保留证据；
- 启动/SDK 诊断：`<项目根目录>\runs\latest\imc60g_startup.log`；程序同时记录该文件的绝对路径。内容包括进程架构、IMC DLL 路径/SHA-256、配置版本、硬件映射、曝光后端以及“仅诊断、卡保持关闭”的证明。部署版本若不能追加该日志，应视为 Task9 集成未完成，不要开始硬件验收。

IMC API 错误采用以下格式：

```text
函数名 failed (card=卡号, physical-axis=物理轴或 n/a,
               code=十进制 [0x十六进制], SDK 符号: 说明. 操作建议)
```

排障时必须完整保留函数名、Card、物理轴、十进制和十六进制错误码、首个故障以及随后追加的清理故障。优先按消息中的中英双语操作建议处理；若显示 `UNRECOGNIZED_IMC_ERROR`，立即停止硬件操作，使用当前部署对应的 `vendor/imc60g/include/errorcode.h` 查询原始数值，禁止凭经验猜测或忽略错误。

## 硬件验收限制

硬件验收必须按“仅发现/无运动 → 显式回零 → 低速小距离 X/Y → 第二屏/VBlank → DO1 安全负载波形 → 单行 → 小型蛇形 → 暂停/继续/取消 → 端到端”的阶段顺序执行，每阶段单独确认，不得自动连续推进。

**没有当次、现场、明确的安全确认时，禁止执行任何会开卡、使能、回零、移动轴或切换 DO1 的验收阶段。** 过去的许可、软件测试通过、第二屏测试通过或设备曾经正常，均不能替代当次对急停、限位、行程和安全负载的确认。
